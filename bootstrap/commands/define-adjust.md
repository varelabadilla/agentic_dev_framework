# /define-adjust — Refine the Project Definition Draft

## Usage

`/define-adjust {inline text describing changes}`
`/define-adjust {path-to-adjustments-file}`

Examples:
- `/define-adjust Block 3 — add a Comments entity that belongs to a Post`
- `/define-adjust .claude/tmp/define-adjustments.md`

Run this after reviewing the draft generated by `/define`.

---

## Process

1. Parse `$ARGUMENTS` to determine input type:
   - If the argument is a file path that exists on disk → read that file in full
   - If the argument is inline text → use that text directly
   - If a file path is given but does not exist → inform the user and stop

2. Check that `.claude/tmp/project-definition-draft.md` exists.
   If it does not, inform the user:
   "No definition draft found. Run /define first."
   Stop.

3. Read `.claude/tmp/project-definition-draft.md` in full.

4. Apply each adjustment:
   - Modify only what the adjustment specifies
   - Preserve all other content, structure, and block headings
   - If an adjustment is ambiguous, ask for clarification before editing
     that item — apply unambiguous ones first
   - If an adjustment resolves a `[PENDING — needs clarification]` item,
     replace the placeholder with the resolved value

5. Re-evaluate the modified blocks against the four-dimension check:
   - Correctness, Completeness, Consistency, Validity
   - If a new gap is introduced by the adjustment, flag it inline in the draft
     as `[REVIEW — check for consistency with Block X]`

6. Save the updated draft to `.claude/tmp/project-definition-draft.md`.

7. Append to `activity.log`:
   `[{timestamp}] /define-adjust: Definition draft updated — {brief summary of change}`

8. Present the updated draft to the user and ask:
   "Draft updated. Review the changes above and:
   - Run **/define-adjust** to continue refining
   - Run **/define-approve** to confirm and proceed to documentation generation"

---

## Restrictions

- Do not generate any `docs/` files
- Do not modify `CLAUDE.md`, `README.md`, or any project file
- Do not proceed to `/define-generate` automatically
