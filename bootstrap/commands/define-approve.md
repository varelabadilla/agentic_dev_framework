# /define-approve — Approve the Project Definition Draft

## Usage

`/define-approve`

Run this after reviewing the draft generated by `/define` and any refinements
made with `/define-adjust`. This command closes the definition session and
prepares the draft for documentation generation.

---

## Process

1. Check that `.claude/tmp/project-definition-draft.md` exists.
   If it does not, inform the user:
   "No definition draft found. Run /define first."
   Stop.

2. Read `.claude/tmp/project-definition-draft.md` in full.

3. Run a final validation pass against all eight blocks:

   For each block, verify:
   - [ ] Block is present and not empty
   - [ ] No field contains only a placeholder or `{value}`
   - [ ] No unresolved `[PENDING — needs clarification]` items remain
         (warn the user if any exist — do not block approval, but list them)
   - [ ] No `[REVIEW — check for consistency]` flags remain unresolved
         (warn the user — do not block approval, but list them)

4. If warnings exist, present them to the user:
   "The following items are unresolved in the draft:
   {list of pending/review items}

   These will appear as gaps in the generated documentation.
   You can still approve and generate now, or run /define-adjust to resolve them first.
   Reply **approve** to proceed or **adjust** to continue refining."

   Wait for the user's explicit response before continuing.

5. If no warnings exist, or the user replied **approve**:

   a. Update the Status line in the draft:
      `Status: Approved — ready for /define-generate`

   b. Append to `activity.log`:
      `[{timestamp}] /define-approve: Definition draft approved. Ready for /define-generate.`

   c. Inform the user:
      "Definition approved and locked.

      Run **/define-generate** to create your project documentation files."

6. **Do NOT generate any `docs/` files.**
   **Do NOT modify `CLAUDE.md` or `README.md`.**
   `/define-approve` only validates and locks. `/define-generate` generates.
