# /proposal-approve — Confirm and Write the Phase Generated from a Proposal

## Usage

`/proposal-approve`

Run this after reviewing the draft generated by `/proposal-to-phase`.

## Process

1. Confirm that a phase draft is present in the current session context
   (generated by the most recent `/proposal-to-phase` run).
   If no draft exists, inform the user:
   "No phase draft found. Run /proposal-to-phase {path} first."
   Stop.

2. Read `docs/development_plan.md` in full.

3. Write the phase file to `docs/phases/phase-NN-slug.md` (or `phase-NN-N-slug.md` for sub-phases — see `.claude/rules/phase-workflow.md`) using the approved draft.

4. Update `docs/development_plan.md`:
   - Add the new phase row to the Phase Overview table with status `⏳ Pending`
   - Add the phase file link to Section 3 (Phase Detail Files list)

5. Update the proposal file (`docs/proposals/proposal-{NNN}.md`):
   - Change the Status line from `Draft — pending review` to:
     `Converted to Phase N — {date}`

6. Verify all edited files:
   - No broken markdown tables
   - No unclosed code blocks
   - Checkbox syntax is exactly `- [ ]`

7. Stage all changed files:
   ```bash
   git add docs/phases/phase-NN-slug.md docs/development_plan.md docs/proposals/proposal-{NNN}.md
   ```

8. Append to `activity.log`:
   `[{timestamp}] /proposal-approve: Phase N created from proposal-{NNN}.md`

9. Inform the user:
   "Phase N written to docs/phases/phase-NN-slug.md
   development_plan.md updated.
   proposal-{NNN}.md marked as converted.

   Commit message:
   `chore: add phase N from proposal-{NNN}`

   When ready to implement, run /plan phase-N."
